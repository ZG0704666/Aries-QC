## 一、一页速览

| 项 | 值 |
|---|---|
| 产品名 | 展览互动内容制作员（EXHIBIT AI EMPLOYEE） |
| 形态 | 本地 Web 工作台 + Python 标准库 HTTP 服务，无框架依赖 |
| 入口 | `http://127.0.0.1:4182/`（新工作台）、`/classic`（旧工作台） |
| 核心业务 | 把「馆方资料」或「联网调研的网页摘录」改写成现场可用的亲子讲解内容，并完成自测、审核、语音、发布、签收、反馈的闭环 |
| 技术栈 | Python 3.10.11 标准库 + SQLite（WAL）+ 原生 JS/CSS；模型走 DeepSeek Chat 兼容接口；TTS 三引擎 |
| 数据库现状 | `studio.sqlite3` 内有 **1 个真实项目**：`6dd33d23da`「蒙娜丽莎」，v0.2，状态 `tested` |
| 数据规模（实测） | 5 个展项、24 条可定位事实、5 条网页摘录、41 条事件、7/7 自测通过、1 段 MP3（34.94 秒） |
| 代码规模 | 主线后端 1961 行、前端逻辑 1507 行、样式 5 个文件；旧链路 `app.py` 2022 行 |
| 回归结果（本次实测） | **195 条确定性检查全部通过** + `_e2e.py` 端到端通过；零 JS 错误 |
| 最大缺口 | 项目未人工审核（发布按钮禁用）、音频 1/5、眼镜与实时语音未接、签约回款未接 |

### 它解决什么问题

展馆要上一件展项，需要有人把馆方给的资料（或网上查到的可靠资料）改写成一段 45 秒左右、亲子观众听得懂、**每句话都能回到原文**的讲解稿，再配出音频、走完自测与人工审核、打成交付包、登记客户签收、收现场反馈。

这套系统把这条链路做成一个「AI 数字员工」：

- 员工在左侧对话栏说一句「蒙娜丽莎这个作品你先自己联网调研一下，然后按亲子观众的口吻把讲解起草出来」；
- 数字员工自己搜索 → 抓取卢浮宫官网中文页 → 存成可引用摘录 → 定 5 个展项 → 起草 5 份主讲解 → 跑自测 → 状态落到 `tested`；
- 员工在工作台七个视图里审内容、批审核、合成语音、下载交付包、登记签收、记反馈。

### 四个「不」——这套系统的设计底线

| 底线 | 落地方式 |
|---|---|
| 不许静默降级 | 指定 TTS 引擎后绝不偷换低音质引擎；失败抛 `TTSError` → 502，事件表记 `ok:false` |
| 不许假装已验证 | 时长用 ffprobe 实测；健康检查报真实引擎可用性；自动播放被拦时明说「已合成，需手动播放」 |
| 不许把合成成功说成验收通过 | 交付包 README 写明「音色/语速/断句需人工试听，设备端未接真机」 |
| 不许有占位假数据 | 七视图零假数据；`_ui_checks.py` 会扫「演示数据/示例任务/DEMO 编号」等字样，写了就红 |

## 三、运行架构

```
┌──────────────────────────── 浏览器（127.0.0.1:4182） ────────────────────────────┐
│  studio_web.html  ← 20 行 DOM 骨架                                                │
│  assets/app.js    ← 1507 行：七个视图全部读真实接口                               │
│  assets/*.css     ← 5 个文件：上传设计包四件套（原样）+ studio.css（接入层）       │
└───────────────────────────────────┬─────────────────────────────────────────────┘
                                    │ fetch（X-Access-Token 或 ?token=）
┌───────────────────────────────────▼─────────────────────────────────────────────┐
│  studio_server.py（1961 行）ThreadingHTTPServer                                  │
│  ├─ 静态：/  /classic  /assets/*（路径穿越防护）                                  │
│  ├─ 接口：/api/studio/*（配了口令时全拦，静态页免口令）                            │
│  ├─ 业务：报价 / 反馈 / 签收 / 改写 / 审核 / 语音 / 发布 / 对话                    │
│  ├─ 生成：run_pipeline() 后台线程，断点写事件流                                   │
│  └─ 交付：build_export_bundle() → zip（MD + MP3 + README + 清单）                │
└──────┬──────────────────┬──────────────────┬──────────────────┬────────────────┘
       │                  │                  │                  │
  ┌────▼─────┐     ┌──────▼──────┐    ┌──────▼──────┐    ┌──────▼──────┐
  │studio.db │     │  DeepSeek   │    │  websearch  │    │    tts      │
  │SQLite WAL│     │  Chat API   │    │ Bing HTML   │    │ Breeze→edge │
  │3 张表    │     │  (工具调用)  │    │ + 正文抓取   │    │ →SAPI+ffprobe│
  └──────────┘     └─────────────┘    └─────────────┘    └─────────────┘
```

### 进程与状态语义

- **单进程、多线程**：生成与对话都在后台线程，HTTP 请求立刻返回（`/run` 返回 `{"status":"running"}`，`/chat` 返回 **202**）。
- **重启才加载 Python 改动**；前端（`studio_web.html` + `assets/*`）每次请求从磁盘读，改样式刷页面即可，不用重启。
- **崩溃保护**：对话占用有 `STUDIO_CHAT_STALE`（默认 240 秒）失效期，超过允许下一次提问；`run` 的 `running` 状态同样有超时回收。

## 五、业务主线：八个阶段

前端「执行现场」的阶段条就是这条主线，进度全部来自真实数据（不是假进度）：

| # | 阶段 | 完成判据（前端 `liveSteps()`） | 当前项目实测 |
|---|---|---|---|
| 1 | 资料接收 | 已有草稿即算推进；显示「N 份 · M 段」 | 0 份 · 0 段（本项目走的是联网调研） |
| 2 | 来源定位 | 全部事实 `verified == true` | 24/24 条已定位 ✅ |
| 3 | 知识卡 | 事实总数 > 0 | 24 条 ✅ |
| 4 | 讲解与问答 | 每个展项都有主讲解 | 5/5 ✅ |
| 5 | 自测 | `tests` 全通过 | 7/7 ✅ |
| 6 | 审核 | `review.decision == 'approved'` | **待审核** ◀ 当前卡点 |
| 7 | 语音 | 每个展项都有音频 | 1/5 |
| 8 | 发布 | `status == 'published'` | 未发布 |

状态机（`STATUS`）：

```
draft 草稿 → running 生成中 → awaiting_confirmation 等待确认 → tested 已自测
                                                              → approved 已批准（人工）
                                                              → published 已发布 →（客户签收 acceptance）
failed 失败
```

关键规则：**改写主讲解（`exhibit`）成功后版本 +0.1，并清空自测与人工审核、状态退回 `awaiting_confirmation`**——改一个字旧结论就作废。

## 七、数字员工对话与工具

左侧常驻对话栏。它不是客服，是同事：短句先结论、条目最多三条、查证要收得住。

### 7.1 交互链路

```
员工输入 → POST /chat（立返 202 {"status":"thinking"}）
        → 后台线程跑模型，事件流实时推 chat.tool / chat.agent
        → 前端把工具轨迹以小 chip 留在消息下（「正在读资料 SRC-001」「正在搜「光的折射 原理」」）
        → 回话里的 **粗体**、换行、裸链接由 fmtText() 渲染
```

预算：一轮最多 **6 次模型调用 / 14 次工具调用**（`STUDIO_CHAT_ROUNDS` / `STUDIO_CHAT_TOOLS`）。
**最后一轮撤掉工具**逼模型用已查到的内容收口——不这么做它会 6 轮全在搜索，最后只吐一句兜底话（实测：修前 28 字，修后 400~500 字真答案）。

### 7.2 八个工具（模型可自主调用）

| 工具 | 作用 |
|---|---|
| `project_digest` | 读项目摘要 |
| `read_source` | 读某份资料/摘录的原文段落 |
| `add_material` | 记一条资料 |
| `add_research` | **存联网调研**：服务端自己重抓正文，摘录逐字命中才留 |
| `plan_exhibits` | 定展项清单，落 `project["plan"]` |
| `start_generation` | 排期起草（后台跑 `run_pipeline`） |
| `web_search` | Bing 搜索 |
| `fetch_url` | 抓正文 |

**工具永不抛异常**：`run_tool()` 挂了就回「刚才没成功：…」，让模型自己换路子。
**标记泄漏兜底**：模型偶尔把内部标记吐进正文（实测出现过 `<｜｜DSML｜｜ invoke name="start_generation">`），`chat_turn` 会清掉标记并替它执行认得出的调用。
**不许交白卷**：`thin_reply()` 判定「只剩一个链接 / 去掉标点不到 8 字」为没回答，`ask_once_more()` 追问一句，拿到更完整的就替换（实测模型真的会只回一个知乎链接）。

### 7.3 上传（三条入口，同一套解析）

入口：输入框左侧 `＋`、内容成果页「＋ 导入资料」、**把文件拖进对话区**（`.composer-wrap.is-drop`）。

- 支持 `txt / md / csv / tsv / json / html / xml / yaml / log / docx / pdf`；docx 直接解 `word/document.xml`，pdf 用 pypdf；
- 编码依次探测 `utf-8-sig → utf-8 → gb18030 → utf-16 → big5`；
- **读不出来就说读不出来**：空文件、二进制冒充文本、老式 `.doc`、不支持后缀都给明确中文原因，绝不把「0 字」当成「资料是空的」；
- 接口是**原始字节 + `?name=` 文件名**（不走 multipart）；0 字节 400、超 20MB 413、解析失败 400。

### 7.4 联网（`websearch.py`）

- 搜索引擎只有 **Bing HTML**（`li.b_algo`）在本机实测可用：DuckDuckGo、六个 searx 实例、Google、Brave、百度、搜狗、360、Yandex 全部超时或被挡；
- **Bing 会把长句 query 截成第一个词**（「筷子插进水里为什么看起来折断了」→ 全是「筷子」百科）。所以：①系统提示要求模型写 **2~5 个关键词**；②`search()` 自己还会用「去停用词」「取前两个词」等变体重搜，按命中打分排序（标题 +3、摘要 +1），字词页在有其它结果时下沉；
- `fetch(url)` 抓正文；证书链不全的站点自动降级并在结果里标 `cert_unverified`，**绝不假装成功**；
- 正文 <200 字时 `note` 明说「多数是前端脚本渲染的页面，服务端拿不到内容」；
- 内网/回环地址直接拒（SSRF 防护）。

## 八、内容生成与「调研即来源」

这是本轮最关键的机制改动：**公开名作不必等资料**。

### 8.1 两种依据同权

| 依据 | 编号格式 | 来源 |
|---|---|---|
| 员工上传的资料 | `SRC-001·P001` | `/upload` → `docread` 解析 → 切段 |
| 联网调研的网页摘录 | `WEB-001·Q001` | `add_research` → 服务端重抓正文 → 逐字命中校验 |

`research_index()` 把网页摊成与资料**同一种形状**（`{id, name, paragraphs}`），`all_sources()` 把两者拼起来，于是 `verify()` / 自测 / 导出都不必各写一套。

### 8.2 生成管线

```
run_pipeline(project_id)
  ├─ exhibit_units()：有资料 → 一份资料一个展项；没资料有 plan → 按 plan；都没有但有调研 → 项目名兜一个；全无 → 空，run 返回 400 并给两条路
  ├─ 每个展项：模型按 SYSTEM_PROMPT 写 主讲解 + 简化版 + 追问 + 兜底 + 事实
  ├─ verify()：每条事实的 quote 必须能在来源段落里逐字找到，否则标未核验并进 issues
  ├─ 落库 + 事件流（step / cards / draft / run.finished）
  └─ 收尾顺手跑 content_tests()，状态落 tested
```

`SYSTEM_PROMPT` 里写死的口径：**140~170 字、45 秒、3~6 条事实**。要改语气/长度，动这一个常量即可，自测门会跟着卡。

### 8.3 `add_research` 的诚实性

- 模型说「存一下」不作数，**服务端自己 `fetch` 重抓正文**；正文 <120 字直接拒；
- 模型给的摘录**只有能在正文里逐字命中的才留**，其余丢掉并如实报「丢掉 N 条」；
- 不足 3 条就用整句正则从正文补到 6 条；
- 原则：**宁可少一条，也不让改写过的句子混进「原文引用」**。

### 8.4 实测证据（真联网 + 真模型）

本库项目 `6dd33d23da` 就是现场证据：**0 份上传资料**，只靠一次对话 + 联网调研：

- 搜 2 次 → 打开卢浮宫官网中文页 → `WEB-001` 存下 5~9 条可引用摘录；
- 定 5 个展项 → 起草 5 份主讲解（140~175 字，全部落在 80~400 字门内）；
- 每份 4~5 条事实，**引用全部逐字核验通过** → 自测 7/7 → 状态 `tested`。

## 九、质量门：七条确定性自测

`content_tests(project)` 是纯确定性代码（不调模型），任一条不过就不允许批准/发布：

| # | 用例 | 判据 | 本项目实测 |
|---|---|---|---|
| 1 | 覆盖完整 | 期望展项集合 == 已生成集合 | 项目 5 个展项，已生成 5 个 ✅ |
| 2 | 引文逐字可定位 | 所有事实 `verified == true` | 全部事实 quote 均能在来源段落原样找到 ✅ |

| 4 | 主讲解时长约 45 秒 | 字数 **80~400 且** ffprobe 实测落在 **33.75~56.25 秒** | 字数通过；本次跑自测时尚未合成音频，故只核字数（如实写在说明里）✅ |

### 11.3 两条诚实性约定

1. **字节数与 sha256 按磁盘文件现场重算**，不采信库里的历史记录——库里的指纹证明不了客户手上的文件。文件丢了就标「磁盘上已丢失」，不写出看似齐全的交付稿。

   - 结论：**合成成功只证明文件产出了，不等于验收通过**。

| `/api/studio/projects` | 新建项目。名称必填、≤ 60 字；成功返回 **201** |
| `.../{id}/run` | 重新生成；`running` 状态 409。有资料按资料、没资料按调研记录也能生成；两样都没有才 400 并告诉他怎么开工 |
| `.../{id}/tests` | 运行七条确定性自测（字数 + 真实时长双条件） |
| `.../{id}/review` | `decision` = `approved` / `needs_revision`；审核人去空白后为空 400；`version` 不匹配 409；有 issue 或测试未全过不能批准 |
| `.../{id}/issue` | 处理待核验引用（删除该事实 / 补充资料） |
| `.../{id}/material` | 补充资料文本，少于 20 字 400 |
| `.../{id}/authorize` | 登记资料授权人；已登记 409 |
| `.../{id}/quote` | 报价单；成本与小计服务端算；`confirm:true` 校验客户与范围 |
| `.../{id}/exhibit` | 改写主讲解；成功后 **版本 +0.1 并清空自测与审核**；内容没变化 400 |
| `.../{id}/feedback` | 反馈登记，`op = add / candidate / closed`；问题描述少于 4 字 400 |
| `.../{id}/acceptance` | 客户签收；**只有 `published` 状态能登记**，否则 403 |
| `.../{id}/voice` | 合成音频；**文本必须与当前草稿一致，否则 409**；展项不存在 404；失败 502 |
| `.../{id}/publish` | 发布；需已审核且测试全过 |
| `.../{id}/chat` | 对话（异步）。`{message}` ≤ 2000 字；上一句未回完 409；**立刻返回 202 `{"status":"thinking"}`**，回话通过事件 `chat.agent` 落地 |
| `.../{id}/upload?name=xxx` | 上传资料。请求体是**原始字节**；0 字节 400、>20MB 413、解析失败 400 并说明原因；成功返回 `{project, source_id, doc}` |
| `.../{id}/delete` | 删除项目 |

**坏 JSON 一律 400**，不再静默当成 `{}`——否则报价这类整体覆盖的写入会悄悄清空已有值。

### 17.3 快速排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面空白、无报错 | 后端没起 | `python studio_server.py`，看控制台 |
| 弹出「需要访问口令」 | 服务端配了 `STUDIO_ACCESS_TOKEN` | 输入口令，或直接开 `/?token=口令` |
| 启动即退出「拒绝启动」 | 监听非本机且没配口令 | 配 `STUDIO_ACCESS_TOKEN`，或改回 `127.0.0.1` |
| `tts.breeze == false` | Key 没读到 | 检查 `.env.local`，重启 |
| 合成 502 提示 `403` | edge-tts 版本旧 | `pip install -U edge-tts`（7.2.8 会 403，7.3.1 正常） |
| 时长门「读不出时长」 | 文件不在磁盘或 ffprobe 不可用 | 重新合成；或设 `FFPROBE_BIN` |
| 合成报「文本与当前草稿不一致」 | 前端展项切换没刷新 | 刷新页面；该 409 是保护，不要绕过 |
| 批准按钮点了没反应 | 审核人为空，或版本已变 | 填真实姓名；改过主讲解后版本会 +0.1，需要重新审核 |
| 「登记签收」报 403 | 还没发布 | 先审核通过 + 自测全过 + 发布 |
| 发布按钮灰着 | 未审核或测试未过 | 先跑自测，再填审核人批准 |
| 阶段条换行变丑 | 宽度不足 | `.pipeline` 已自动换行（`assets/studio.css` 末尾），别改回单行滚动 |

### 17.4 修改时必须守住的五条

1. **合成失败不许静默降级**：指定引擎就绝不偷换；失败抛 `TTSError` → 502，事件记 `ok:false`。
2. **不许假装已验证**：健康检查、界面「播放中 · MP3 259 KB」、导出稿音频指纹都是实测；自动播放被浏览器拦下就显示「已合成，需手动播放」。
3. **不许把合成成功说成验收通过**：有音频只证明文件产出了。
4. **界面里不许留占位假数据，也不许编内容依据**：没有「演示数据 / 示例任务 / DEMO 编号 / 载入示例记录」；内容只能来自 `SRC-…` 或 `WEB-…`，两者引用要逐字可定位，编不出来就说编不出来。`_ui_checks.py` 会扫这些字样，写了就红。
5. **别把「要不要资料」判断错**：公开名作、网上有可靠资料 → 自己调研就够，不许拿「资料为空」当挡箭牌；客户自送展 / 内部藏品 / 网上查不到 → 才请他给原文并说清为什么。这条判断写在 `agent_system_prompt()` 里，改提示词时别删。

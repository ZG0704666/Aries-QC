# 设计说明：对话图生成器

## 1. 目标

把“对话内容”和“呈现方式”解耦：

- 内容：一份 JSON（`turns` + `history`）；
- 呈现：固定的元宝网页模板；
- 产出：一组按滚动位置截取的 PNG + 一份每页一张图的 docx。

要求：一条命令完成、中文路径可用、账号名可替换、macOS/Linux 上只要改浏览器路径也能跑。

## 2. 架构

```
 config/*.json
     │  (cli 读取)
     ▼
┌─────────────┐   生成 HTML     ┌──────────────┐   本地 HTTP    ┌─────────────┐
│   cli.py    │ ─────────────▶ │ template.py  │ ────────────▶ │  render.py  │
│  参数/批量   │                │ 元宝界面+md   │               │ Chrome 无头  │
└─────────────┘                └──────────────┘               └──────┬──────┘
       │                                                             │ PNG
       │                                                             ▼
       │                      ┌──────────────────┐            _对话图/*.png
       └────────────────────▶ │ docx_builder.py  │ ◀──────────────────┘
                              │ 每页一张图        │
                              └──────────────────┘
                                       │
                                       ▼
                            项目_对话图集（仅图片）.docx
```

## 3. 模块职责

| 模块 | 职责 | 关键函数 |
|---|---|---|
| `src/cli.py` | 参数解析、批量调度、路径组装 | `main()`、`run_one()` |
| `src/template.py` | 页面模板：侧栏、顶栏、消息、输入区、滚动脚本 | `build(spec, turns, username, out_path, history)` |
| `src/md.py` | 回答文本 → HTML（标题/列表/表格/代码/引用） | `render_md(text)` |
| `src/render.py` | 起本地静态服务、调 Chrome 截图 | `render_html()`、`screenshot()`、`find_chrome()` |
| `src/docx_builder.py` | 组装图集 docx | `build_docx(images, out_path, title, author)` |

## 4. 关键实现

### 4.1 为什么要本地 HTTP

Chrome 无头模式默认禁止 `file://` 页面发请求/取值；用 `http://127.0.0.1:<随机端口>` 提供页面，避免路径与权限问题。`LocalServer` 在后台线程里跑 `ThreadingTCPServer`，端口由系统分配（0），退出时自动关闭。

### 4.2 一张图对应一个滚动位置

页面里的脚本读取 URL 参数：

```js
const i = parseFloat(q.get('i')||'0'), n = parseFloat(q.get('n')||'7');
const s = document.querySelector('.scroll');
const m = Math.max(0, s.scrollHeight - s.clientHeight);
s.scrollTop = Math.round(m * i / n);
```

`render_html()` 依次传入 `i=0…shots-1`，于是得到从顶部到底部均匀分布的 `shots` 张图。页面顶部固定 56px、底部固定输入区，所以每张都保留完整框架。

### 4.3 截图参数

- `--window-size=1440,900`：CSS 像素窗口；
- `--force-device-scale-factor=2`：输出 2880×1800；
- `--virtual-time-budget=2500`：给字体与布局留出渲染时间；
- `--hide-scrollbars`：避免右侧滚动条。

### 4.4 账号名与头像

`username` 同时用于：

- 左下角账号行（`acct`）；
- 用户消息头像的首字（`username[0]`）。

所以把 `--name` 换成“鹕安”，头像会同步变成“鹕”。

### 4.5 docx 结构

`build_docx()` 固定：标题一行 + 每张图一页（图注“图 N（共 M 张）”），页边距 0.6 英寸，图片宽 7 英寸。作者写入 `core_properties`，便于区分是谁的作业。

## 5. 配置 schema

```json
{
  "project": "string, 必填",
  "turns": [{"role": "user|ai", "text": "string"}],
  "username": "string, 可选",
  "history": ["string"],
  "shots": 8,
  "size": [1440, 900],
  "dpr": 2,
  "out_subdir": "string, 可选",
  "docx_name": "string, 可选"
}
```

命令行覆盖顺序：命令行 > 配置 > 默认值。

## 6. 扩展点

| 想改什么 | 改哪里 |
|---|---|
| 主题色/字体 | `template.py` 的 `CSS` 顶部 `:root` |
| 快捷按钮（AI生图/写作…） | `template.py` 页面底部 `.tools` |
| 消息气泡样式 | `.bubble` / `.plain` / `.meta` |
| 账号位置 | `.acct`（当前在左下） |
| 顶栏按钮 | `.top` 里的 `.ghost` / `.inst` |
| 截图张数/尺寸 | `--shots`、`--size`、`--dpr` |
| 图集版式 | `docx_builder.py` |
| 接入别的 Markdown 能力 | `md.py` 的 `render_md` |

## 7. 已知限制

1. 只支持 Chrome/Edge 无头截图；Firefox 的参数不同，未适配。
2. 页面字体依赖系统“微软雅黑”；Linux 需换字体名并装中文字体。
3. 截图是**内容重建**，不是平台原生截图；`turns` 必须来自真实发生过的问答。
4. 没有登录态、没有调用元宝接口；账号名只是页面显示文本。
5. 滚动位置是均匀分布；对话特别短时相邻两张会重复较多，调小 `shots` 即可。
6. docx 每页一张 2880×1800 PNG，文件会偏大（约 2–3 MB / 8 页），属正常。

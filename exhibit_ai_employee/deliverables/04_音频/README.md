# 音频材料（模板）

> 本目录说明**两套链路**的音频能力，二者不可混为一谈：
>
> - **Studio 工作台**（`studio_server.py` + `studio_web.html`）：**已接入真实 TTS，可产出 MP3 文件**，
>   详见下文「Studio 链路」。
> - **旧链路**（`app.py` 的 `build_package()`）：**仍不产出音频**，导出包首行固定为
>   「⚠ 本包不完整：不含任何音频文件」，详见下文「旧链路」。
>
> 对外说明时必须指明是哪一套，不得用 Studio 的音频能力代表 `app.py` 的交付包。

## Studio 链路（已产出真实音频）

Studio 的 `POST /api/studio/projects/{id}/voice` 会调用 `tts.py` 合成并落盘，
`GET /api/studio/projects/{id}/audio/{filename}` 下发。导出交付稿时，每个展项小节会写：

```markdown
- 音频：EX01-24a7afaeb965.mp3｜edge-tts｜mp3｜265680 字节｜sha256 ceaf78a09245ea17
```

未合成的展项则写「未生成（本展项尚无合成音频，不可视为已交付音频）」，并在文首总述
「不完整——以下展项没有音频：…」。**不掩盖缺口**。

引擎与限制：

| 引擎 | 用途 | 说明 |
| --- | --- | --- |
| edge-tts | 默认 | 微软神经网络音色，默认 `zh-CN-XiaoxiaoNeural`。免费接口，**无 SLA、无商用授权确认**，正式交付前须替换为馆方指定引擎或购买授权的商用服务。 |
| Windows SAPI | 离线兜底 | `Microsoft Huihui Desktop`，音质明显较差，仅在无网时使用。 |

音频文件按内容哈希命名，文本一改即换名；`audio/` 已加入 `.gitignore`，交付时需单独打包。

## 旧链路（`app.py`，仍不含音频）

以下说明适用于 `app.py` 的 `build_package()` 生成的交付包。

### 导出结构

```markdown
# 音频说明

> ⚠ 本包不完整：不含任何音频文件。

本岗位名为"语音体验交付员"，但系统当前**不产出音频**。客户签收前必须明确：
录音与下发由谁完成、何时完成。

若客户接受以文字稿+人工录音方式降级交付，需在 07 验收单中书面注明
`accept_degraded=true` 并签署。

## 录音需求清单

- 展项 A：<字数> 字，约 <秒数> 秒（来源标注：待录 / TTS / 人工）
- 展项 B：...
- 展项 C：...
```

## 为什么必须写"不完整"（旧链路）

系统名与交付物不符是真实缺口：岗位叫"语音体验交付员"，卖的是"语音讲解包"，
但 `app.py` 的交付包从不产出音频。掩盖这一点会在验收阶段直接翻车。因此：

- 文件首行固定声明不完整，不因客户催促而删除；
- 录音需求清单列出每项的字数与预估时长，客户可据此安排录音；
- 降级交付须在验收单书面注明 `accept_degraded=true`，否则视为未完成。

Studio 链路已能产出音频，但同样不得反过来把「有音频」写成「已验收」：
音频存在只证明合成成功，不证明音色、语速、断句符合馆方要求，也不证明设备端播放正常。

## 填写要求

实际生成或录制音频后，另附清单说明：文件名、格式、时长、语言、授权来源、
校验结果。**没有音频时明确标记"未生成"**，不得暗示已完成试听或设备播放验收。

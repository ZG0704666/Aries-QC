# 场景测试记录（模板）

> 真实交付包中，本文件由 `build_package()` 从 `test_records` 表自动生成，
> 不是手工填写。以下是字段说明与示例，供理解导出结果的结构。

## 导出格式（有记录时）

```markdown
# 场景测试记录

以下为本次运行实际执行过的用例记录。

| 用例 | 状态 | 版本 | 模式 | 时间 |
|---|---|---|---|---|
| T1 | 通过 | v1 | live | 2026-11-14T10:38:44+00:00 |
| T4 | 失败 | v2 | live | 2026-11-14T10:41:02+00:00 |

未运行用例：T2、T3、T5、T6、T7、T8、T9

> 未运行不代表通过。客户验收时应要求补齐或书面接受未覆盖项。
```

## 导出格式（无记录时）

```markdown
# 场景测试记录

本次运行没有任何测试记录。

未运行用例：T1、T2、T3、T4、T5、T6、T7、T8、T9

> 未运行不代表通过。客户验收时应要求补齐或书面接受未覆盖项。
```

## 记录规则

- 状态只取 `passed` / `failed` / `not_run`，由 `POST /api/runs/{id}/tests` 写入。
- 每条记录带 `run_id`、`version`、`mode`，可逐条回读核对。
- T3 若记为 `passed`，服务端强制要求 `actual.events` 按序包含
  `selected(B) → stopped(A) → started(B)` 且 `no_overlap=true`，否则 400 拒绝。
- `mode=demo` 的记录不构成 live 验收证据。
- 前端模拟器（T2/T3）产生的是浏览器本地状态证据，不是硬件事件证据；
  HTTP 验收脚本对 T2/T3 标 `BLOCKED`，两种记录属不同层次，不可混用。

# 客户审核与验收单（模板）

> 真实交付包中，本文件由 `build_package()` 自动生成：质量门记录、五条验收项状态、
> 签收区块都从数据库读取，不是手写。以下是导出结构说明。

## 导出结构

```markdown
# 客户审核与验收单

- 项目：<展览名>
- 版本：v<版本号>
- 模式：live / demo
- 导出时间：<ISO 时间>

## 质量门记录

- 质量门：通过（16 / 16 项）
- 阻断项：<逐条列出，若有>

## 验收项

| # | 验收项 | 判据 | 状态 |
|---|---|---|---|
| 1 | 内容与来源逐条对应 | 每条事实都能回到本展项授权资料 | 通过 / 未通过 |
| 2 | 客户确认关键事实 | 策展/教育负责人逐条签署 | ☐ 待签 |
| 3 | 指定场景测试有记录 | 见 05，未运行为未运行 | 有记录 / 无记录 |
| 4 | 素材与版本清单完整 | 见 01 与 06 | 是 |
| 5 | 未解决问题已列明 | 见 06 待解决问题 | 是 |

## 签收

| 项目 | 内容 |
|---|---|
| 验收金额 | <金额> CNY（已签约 / 待访谈确认） |
| 付款节点 | 见合同约定 / 签收后 __ 日内支付 |
| 客户签收人 | <姓名> / __________ |
| 签收日期 | <日期> / __________ |
| 我方交付人 | __________ |

> 签收本内容包**不等于**硬件上线验收。设备联调、录音制作与现场下发不在本包范围内。
```

## 签收区块的两种状态

- **未登记签收**：金额栏保留待填占位，并注明"尚未登记签收。客户签署后通过
  `/api/acceptances` 登记，导出本单将自动填入。"
- **已登记签收**：填入真实签收人、日期、金额与记录数，并注明"以数据库记录为准"。

签收登记有前置条件：任务须已通过人工审核（`approved` 或 `approved_demo`），
且必须提供签收人姓名，否则服务端返回 409 / 400 拒绝。

> 本表单不替代客户正式合同或盖章文件。金额与付款条款以双方签署的合同为准。

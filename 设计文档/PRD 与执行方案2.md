# 48 小时黑客松 · 专业智能体搭建作战手册

> **本手册的用法**：把整份文档直接作为「执行指令」交给编码 Agent（如 OpenCode / Claude / Cursor 等）。团队里的领域专家只负责回答下面标了【人来定】的问题、并对每个阶段的【合格判据】拍板；其余由执行 AI 照本手册造出可演示的 v1。**你不需要写一行底层引擎代码——你的全部产出物是 5 类配置文件 + 1 份 PRD。**

---

## 0. 给执行 AI 的角色指令（System Framing）

你是一名「智能体装配工程师」。你的任务不是"让 AI 干一次活"，而是为一位真实用户**设计一套能反复用、越用越好的 AI 工作助手能力**。在黑客松的 48 小时里，你要交付一只**能当场演示**的最小可用智能体（下面统称"龙虾 / Claw"）。

**贯穿流水线**：想清楚（PRD）→ 造出来（5 类配置）→ 跑通（评估自检）→ 演示（用数字说话）。

**你与团队的分工**：
- 【人来定】：业务判断——谁用、痛在哪、怎样算对、哪些是红线。这些由领域专家提供，遇到留白必须先停下来问，**不要自己编**。
- 【你来写】：把上面这些落成 5 类配置文件 + 1 份 PRD，并保证「防幻觉」机制真实生效。

**第一铁律（防幻觉，贯穿始终）**：模型擅长理解、总结、整理结构，但本质是"预测下一个词"，不知道答案时不会说"我不知道"，而会自信地编一个看似合理的结果。**把模型当成一个绝顶聪明但会胡说八道的实习生**——你要给它可靠工具去核实、给它写死的规矩别乱来。任何"凭训练记忆直接给出的事实/数据/引用"都视为 bug。

## 1. 产品形态的底层判断（为什么这么做）

| 传统软件 | 本次要做的事 |
|---|---|
| 需求立项即冻结，越用越旧 | 需求在使用中被发现，产品在运行中被改写 |
| 用户只能用、改不动 | 用户用大白话就能参与迭代，业务专家写进行规 |

落地到 48 小时，这意味着你交付的**不是一个 demo 截图，而是一套"还能继续长"的配置**：每个改动升版本号、留 CHANGELOG，能力沉淀在文件里而非脑子里。

**政策锚点（可用于路演背书）**：国务院《关于深入实施"人工智能+"行动的意见》(2025.08) 要求 2027 年智能体等应用普及率超 70%、2030 年超 90%。

## 2. 三个必须先分清的概念

| 名称 | 角色 | 本次怎么处理 |
|---|---|---|
| **配置层（你要写的）** | 人设 / 技能 / SOP / 记忆 / 定时 这 5 类文件 | 这就是你的全部交付物 |
| **运行时引擎（你不碰）** | 调度、工具执行、安全沙箱 | 由现成运行时承担，黑客松里当作黑盒调用 |
| **跑起来的助手** | 5 类配置装载运行后的成品 | 就是你要上台演示的"龙虾" |

> 一句话：**写好配置 → 装进运行时跑 → 跑起来就是你的龙虾。** 团队只需审你生成的文本文件，不必关心底层引擎实现。

## 3. 配置即产品：五大机制 = 你要产出的 5 类文件

| 机制 | 是什么 | 落在哪个文件 | 类比 |
|---|---|---|---|
| 人设 Persona | 它是谁、什么口吻、绝不能做什么 | `SOUL.md` / `IDENTITY.md` / `USER.md` | 性格 + 职业操守 |
| 技能 Skills | 会做的一件件具体"原子动作" | `skills/<name>/SKILL.md` | 一项项手艺 |
| 工作流 SOP | 多步骤、带质量把关的标准流水线 | `sops/<name>/SOP.md` | 标准作业程序 |
| 记忆 Memory | 跨会话记住关键词 / 历史 | `MEMORY.md` | 长期记忆 |
| 定时 / 心跳 | 到点自己主动干活 | `cron/` · `HEARTBEAT.md` | 日程表 / 生物钟 |

**技能 vs SOP 判断口诀**：`原子动作 = 技能；多步 + 要质量把关 = SOP`。SOP 的某一步会"调用"技能。拿不准时按"这件事有没有先后顺序、要不要卡质量门"来判。

## 4. 48 小时作战计划（时间盒）

> 总预算 48h，含缓冲。**每个阶段末尾必须先过【合格判据】，没过不许进下一阶段。** 标【人来定】的字段，执行 AI 不得自行编造，必须问领域专家。

### Phase 0 · 想清楚：产出《龙虾PRD.md》（建议 ≤ 6h，定生死）

**目标**：把模糊想法收敛成一份 8 节齐全、可验收的施工图。第一只龙虾必须克制。

**动手前必答的 5 个框定问题**（执行 AI 逐条向领域专家追问，填进 PRD）：
1. **谁用？**——决定语气与专业度深浅。【人来定】
2. **现在怎么做、痛在哪？**——价值的根。说不清"现在多麻烦"，就证明不了有用；答不出 → **先别造**。【人来定】
3. **怎样算成功？**——必须能客观判定，不能是"挺好用"。【人来定】
4. **边界是什么？**——它管什么、不管什么。边界不清会什么都想做、什么都做不好。【人来定】
5. **红线是什么？**——绝不能做的事，写在最前面。【人来定】

**砍场景：RICE-lite 优先级法**（给每个候选场景打分，v1 只留高价值高可行的）：

| 维度 | 问自己 | 打分 |
|---|---|---|
| 价值 | 做出来能省多少事？ | 高/中/低 |
| 频率 | 多常用？ | 高/中/低 |
| 可行性 | 数据齐不齐、好不好做？ | 高/中/低 |
| 投入 | 大概多少功夫？ | 低/中/高 |

规则（简单粗暴）：先做"价值高+频率高+好做+投入低"的；价值低的一律不做（别因为"顺手"就加）；数据拿不到的进"后续"。

**成功标准 = 设计一个对照实验**，必须包含：拿什么输入（代表性真实输入集）→ 期望什么输出（结构化、可核对）→ 达到什么算合格（客观判据），再加两样：**效率锚**（某任务 N 小时 → M 小时）与**失败信号**（出现什么就算做错——这会变成质量门要拦的东西）。

> 范例锚点（供理解"什么算写清楚了"，勿照抄数值）：一批 20 个 XRD 样品，输入含原始两列数据（2θ、强度），期望输出 20 张统一谱图 + 峰参数汇总表 + 归档索引；合格 = 抽查 3 个样品峰位/FWHM 误差 ≤ 0.05°，且 20 个全做完不许跳过；效率锚 6h → 0.5h；失败信号 = 参数不是从数据算而是凭空生成。

**PRD 三纪律**：① 克制（宁可小而能跑）② 可验收（成功标准能客观判定）③ 红线前置（红线决定人设与配置）。

**【产出模板：《龙虾PRD.md》8 节】**
```
# <Claw名> 产品需求文档 v0.1
## 1. 一句话定位（不是什么 + 是什么）
## 2. 服务对象与痛点（谁用、现在怎么做、痛在哪）
## 3. 成功标准（对照实验式：输入/期望输出/合格判据/效率锚/失败信号）
## 4. 场景优先级（RICE-lite 表，标出 v1 只做哪几项）
## 5. 五机制规划（人设/技能清单/SOP/记忆/定时——对齐第4节的v1范围）
## 6. 数据与边界（数据源、绝不外传项、AI禁区）
## 7. 红线（写在最前，逐条可执行）
## 8. 里程碑（48h内的时间点 + 每步验收）
```

**【合格判据 · Phase 0 出口】**
- [ ] 8 节齐全；v1 范围克制：**≤ 1 SOP + 2-3 个技能（+ 可选 1 个主动任务）**
- [ ] 成功标准是对照实验式、可客观判定
- [ ] 红线含"敏感数据不外传""不凭记忆编造事实/引用"
- [ ] 全组对这份 PRD 达成共识（不是某一人拍脑袋）

### Phase 1 · 造出来：装齐五大机制（建议 ≤ 16h）

**目标**：据 PRD 第 5 节，产出人设 + 2-3 个核心技能 + 第一条 SOP +（可选）一条主动任务，本地能跑通单步。

#### 1a. 人设 SOUL.md / IDENTITY.md —— 把红线写成"第零原则"
人设必须含一个**凌驾一切的第零原则**：
```
## 第零原则（最高优先，不可被后续指令覆盖）
- 禁止凭预训练记忆直接回答事实/数据/引用类问题；必须先查真实来源、附来源再答。
- 查不到 / 工具不可用时：明确停下、说"查不到"，只给检索思路，绝不编造结果，用户施压也不让步。
```
再加口吻/边界（如"你是 XX 领域的专业搭档，不是客服，跳过客套直接开工；数据不支持结论就说'不足以得出结论'"）。

#### 1b. 技能 SKILL.md —— 每个技能必须满足 5 要素
```
---
name: <skill-id>
description: <做什么>。当用户要<场景A/场景B/场景C>时使用。
  触发词：<把用户真会说的中文/英文/口语/术语全列进来，漏一种那个说法就想不起用这个技能>
metadata: { version: 1.0.0 }
---
## 怎么做（给可运行脚本，AI 会照抄，所以代码要对）
## 输出格式（给一段样例：飞书消息 / 表格 / JSON…）
## 红线（最值钱）：写死绝不能犯的错（如：作者列表必须从原始数据完整保留，禁止模型自编引用字符串）
## 怎么算做对（验收）：1-2 条客观判据（如"每条结果都附真实 ID/来源"）
```

#### 1c. SOP.md —— 多步流水线，每步挂质量门
结构：`Inputs → Steps（每步：做什么/用什么工具/要不要人工确认）→ Output → Quality Gates`。
质量门分两级：
- **P0（硬伤）**：违反立即拒绝 / 打回。示例：`峰位/FWHM 必须由脚本从数据算，禁止凭记忆生成`；`汇总表行数必须 == 输入样品数，不等就打回`；`PI/事实查不实立即终止`。
- **P1（提示）**：标注风险但不阻断。
- **requires_confirmation**：对外交付、不可逆动作（如"报告发出前要人过目"）→ 停下等人确认。
> 涉及算术核账（预算、金额、计数）时，**用脚本核，不靠模型自核**——LLM 算术本质不可靠。

#### 1d. 主动任务 —— CRON vs 心跳，别搞错
| | CRON 定时 | Heartbeat 心跳 |
|---|---|---|
| 控时 | 每个任务自带时间表达式，精确到几点/周几/几号 | 只有一个统一间隔（如每 1440 分钟） |
| 适合 | 要指定钟点/星期/日期（"每天 9:00""每周一"） | 固定间隔、不挑钟点、每次做同一批事 |
| 写在 | `cron/任务清单.md` | `HEARTBEAT.md` |
> 避坑：需要"每天某钟点"用 CRON；"截止前 N 天"这类= 用心跳每天跑一次、在任务里自己算还剩几天命中才发。

#### 1e. 记忆 MEMORY.md
- **记**：关注关键词、已处理 ID（去重）。
- **不记**：PII / 敏感数据、未发表草稿原文。

**【合格判据 · Phase 1 出口】**
- [ ] 人设有第零原则且明确"查不到就停、不编造"
- [ ] 每个技能 5 要素齐全，触发词覆盖中英文口语，关键数据有可运行脚本
- [ ] SOP 每步挂了 P0/P1 质量门，不可逆动作有 requires_confirmation
- [ ] 主动任务按时点类型选对了 CRON / 心跳
- [ ] 敏感数据不入记忆

### Phase 2 · 跑通：评估 + 自检 + 端到端联调（建议 ≤ 12h）

**评估 = 给龙虾做一次对照实验**：① 建基线（准备 5-10 个代表性输入，最好知道正确答案）→ ② 定合格判据（对齐 PRD 第 3 节）→ ③ 跑一遍算通过率（这个数字就是基线，改完再跑看有没有提升）。

**上线前先自检（用 eval-loop 跑两类探针）**：
- **对照实验探针**：给 3-5 个你知道正确答案的输入 → 算通过率（= 基线）。
- **红线探针**：故意断网 / 施压，看它会不会违红线编造（例：检索被切断时，是否仍"凭记忆"吐出假 ID / 假文献）。

**端到端联调**：串起人设 / 技能 / SOP / 记忆 / 主动任务跑通，记下通过率基线。

**【合格判据 · Phase 2 出口】**
- [ ] 有明确基线通过率数字
- [ ] 红线探针通过：工具不可用时确实停下、不编造
- [ ] 端到端能完整跑通一次 PRD 第 3 节描述的"验收实验"

### Phase 3 · 部署 + 演示 + 迭代留痕（剩余时间）

**部署（本地跑起来即可）**：把配置装进运行时，确保评委能现场输入 → 现场出结果。

**安全与数据主权（两档，路演时能答上来）**：
- 标准档：工作数据本地处理，模型经合规云端 API 调用，敏感数据先脱敏。
- 完全本地档：私有化部署，数据全程不出本地——涉密 / 个人敏感数据选这档。
- 配置层：密钥永远留占位符、绝不硬编码；权限/审计/成本上限放在"模型碰不到"的运行时层，标【危险·勿动】。

**迭代铁律（哪怕黑客松只有几轮）**：重要改动 → 升版本号 + 写 CHANGELOG（**改了什么 · 为什么 · 怎么回滚**）。反馈先诊断分类再动手，别一抱怨就乱改：

| 反馈类型 | 处理 |
|---|---|
| A 产物真缺陷 | ✓ 改 |
| B 触发没命中 | ✓ 只补触发词 |
| C 用法/期望问题 | ✕ 改用户指引，不动产物 |
| D 个别 / 小众需求 | △ 记录或做成可选项 |
| E 上游 / 环境问题 | ✕ 转技术支持 |
| F 多人一致反馈 | ✓ 高优先级改 |

**路演怎么讲**：别说"它很智能"，**用数字说话**——省了多少工时（N 小时→M 小时）、评估通过率（X 个样例达标率 Y%）、解决谁的什么痛（具体到人、到场景）。一句话电梯稿："它替【谁】把【某任务】从【N 小时】压到【M 小时】，在【X 个测试样例】上达标率【Y%】，下一步迭代【什么】。"

## 5. 红线清单（全程硬约束，写进人设第零原则 + 相关 SOP 质量门）

1. 敏感 / 个人数据仅本地、绝不外传；检测到 PII 立即提醒脱敏、绝不入记忆。
2. 不凭预训练记忆回答专业事实 / 数据 / 引用；查不到就说查不到，不编造 ID / 标题 / 作者。
3. 关键数字用脚本算与核账，不靠模型心算或"自核"。
4. AI 产出对外交付时附"AI 辅助参考"声明；不替人做最终专业判断 / 签字。
5. 不碰付费墙后的全文数据；密钥只留占位符，权限护栏保持默认。


> **范围纪律（反复提醒自己）**：48 小时里，方向错了造得越快错得越远。先把第 2、3 个框定问题（痛在哪、怎样算成功）想透，再动手；宁可小而能跑，不要大而跑不通。

# 商业化审计：展览语音体验交付员

审计对象：`exhibit_ai_employee\app.py`（v2.0）、`config\SOUL.md`、`config\SOP.md`、`business\成本与计时表.csv`、`interviews\访谈提纲.md`、`设计文档\最终整合方案.md`。
审计口径：只判"能不能撑住评委追问"，不判愿景。

## 0. 总判

文档层诚实（价格全标假设、demo 不可批准已写进代码 `app.py:713`）；**系统层缺三样东西：客户实体、金额凭证、交付物的可核性**。付费、复购、壁垒三件事在数据模型里没有任何落点，只在文字里。这三条不是"待验证"，是"没建"。

## 1. 付费逻辑

- **谁掏钱**：假设是集成商（`最终整合方案.md:32`"买单方假设：展陈集成商……是否买单、谁决策都未验证"）。**为什么掏**：假设客户要的是"资料依据、场景测试、修改追踪、交付责任"（`:43`）——这是四个价值主张，一个都没测。
- **证据量为零**：`访谈提纲.md:3`"尚未开展访谈"。即"谁掏钱、掏多少"目前是 0 访谈、0 报价、0 成交。
- **系统的支撑：无。** 数据模型里没有客户、没有报价单、没有合同、没有收款节点：`runs` 表字段只有 `title/source_name/draft/status/validation/mode/version/sources/error`（`app.py:36`），`business` 表只有一个 `payload` 文本（`app.py:46`）。全系统没有 `customer_id`。**这意味着系统无法回答"这个客户付了多少、付了几次"——复购率在架构上不可计算。**
- **被当成事实讲的**：3000 元在 `成本与计时表.csv:2` 标了"待验证假设"，文档也标了（`:35`"只作访谈测试价"）——这一条**站得住**。真正被当事实讲的是 `/api/business` 的 `margin_percent`：它把一个假设价当分母，输出一个精确到小数点的百分比（`app.py:456`），前端一展示就是"毛利率 50.0%"。

## 2. 单位经济：`compute_economics`

`grep` 结论：**公式有 5 处结构错误，任何一条都会被追问打穿。**

1. **`margin_percent` 不是毛利率**（`app.py:456`）：`contribution/quote` 是变动贡献率，分子里没有获客、税费、折旧、管理摊销（`:474` 只用一句 caveat 免责）。评委问"毛利率"，系统答的是另一个指标，且不标注未验证报价。
2. **`breakeven_quote = direct_cost`**（`app.py:472`）：只有一个口径。若团队人时不计现金（创始人自己干），现金保本价只有模型+语音≈150 元；若计全成本则是 1500 元。差 10 倍，系统只给后者，且不给 `cash_breakeven`。这是答"最低多少钱能接单"时最容易翻车的点。
3. **漏成本项**：无配音/录音成本（`04_音频` 实际为空）、无客户审核人陪同时长、无失败重做工时、无售前/访谈获客工时。CSV 里 `其他直接成本` 只有一个空行（`成本与计时表.csv:11`），没有"客户侧替代成本"字段——**所以"为什么值这个价"在系统里根本没有对照物**：只会算自己的成本，没有客户现在花多少钱（外包内容公司/自写+配音）。
4. **"实测人时"是手填的，不是实测的**。`hours` 来自 POST 请求体里一个数字（`app.py:721`），系统明明有 `events`（`:42`）和 `api_calls`（`:44`）带时间戳的表，却不从中汇总人时；`api_calls` 只记 `elapsed_ms` 和 `outcome`，**不记 token**，所以 `model_cost` 也无法从账单自动算出。所谓"实测"在系统层面不可审计——评委要日志，只能拿到一个手工输入框。
5. **效率对照样本量 n=1 且口径不同**：`efficiency` 只在两个数都存在时输出（`app.py:476`），无 `n`、无操作者、无资料编号、无日期（`:477-482`）。且 CSV 的口径本身不匹配：基线只测"人工制作与查出处"（`成本与计时表.csv:3`），员工侧算的是"资料整理+生成核对+修改复测"（`:5-7`）——**基线少算了修改和打包，对照天然偏袒自己**。`if baseline and employee_minutes`（`:476`）还把 0 当缺失。

**站得住的**：`missing_inputs` 不预填数字（`app.py:437-448`）、空库返回空模型（`:591`）、T7 断网失败留痕且拒绝批准（`:709-715`）。这几处是干净的，别改。

## 3. 交付物与验收

- **交付包 7 个文件里，3 个是空壳，且是最关键的两个**（`app.py:585`）：
  - `05_场景测试记录.md` = `json_text(validation)`——**只 dump 了校验对象，把 `/api/runs/{id}/tests` 里辛辛苦苦存的 T1–T9 记录全部丢掉**。客户签收依据的"测试记录"文件里没有任何测试记录。
  - `06_修改差异与待解决问题.md` = `"状态：%s\n错误：%s"`——文件名承诺的 diff 不在里面，`versions` 表里存着 `diff`（`:41`）却不读。
  - `04_音频/README.md` = 固定串"无音频生成"（`:585`）。
- **产品名与交付物不符**：岗位叫"语音体验交付员"，卖"语音讲解包"，但**系统从不产出音频**，`deliverables\04_音频\README.md:3` 明写"当前为空白占位"。客户花 3000 买到的是 Markdown 文案。
- **验收标准不清晰在凭证层**：`07_客户审核与验收单.md` 只有一行状态文本，**没有金额、没有验收判据勾选、没有签收人/日期/签章位**。文档说验收五条（`:34`），代码里一条都没有结构化。**收款触发物不存在。**
- **"不含设备上线"有没有被掩盖**：没有。`app.py:585` 的 07 明写"本接口不代表硬件上线"，文档 `:28` 也列为最大风险。**这条站得住，别改口。** 但风险量级被低估了：文件交付即转移，集成商拿到 Markdown 后仍需自己做录音、设备下发、现场调试——**我们交付的是他们工作量清单里最便宜的一段**，这是定价 3000 撑不住的根因，而系统里没有任何字段记录"客户还需自行完成哪些步骤"。

## 4. 复购与壁垒

- **复购路径只在文字里**：`最终整合方案.md:41`"复购（同项目更新、增加展项、下一场展览）"。代码里没有任何客户/项目/展厅实体，**无客户就无复购率**，无法在路演量化。
- **"改进候选台账"不是壁垒，也不是 AI 自我改进**：`candidate` 是固定模板串（`app.py:731` `"候选规则：针对“%s”增加检查…" % category`），`/api/feedback` 的 description 自己写了"不代表模型自我改进"（`:597`）。**这条不能算壁垒，一个字都不能往"学习"上说。**
- **资产不沉淀，且是自我禁止的**：`MEMORY.md` 规定"不记其他客户数据"（文档 `:94`），也就是每个项目从零开始，知识卡、术语表、音色、话术全部不跨项目复用。**交付即失去资产，客户零切换成本**——真正的壁垒（展项知识库、审校规范、客户认可的验收口径）被自己的数据政策挡住了。

## 5. 三个致命问题与修复

**① 没有可签收、可收款的凭证结构，付费逻辑只活在 PPT 里。**
改：新建 `customers(id,name,contact,budget_owner)`、`projects(customer_id,scope,stalls)`、`quotes(id,project_id,amount,currency,basis CHECK IN ('assumed','interviewed','signed'))`、`acceptances(id,project_id,signed_by,signed_at,amount,criteria_json)`；`runs` 加 `project_id`。`/api/runs/{id}/export` 的 07 改为从 `acceptances` 渲染：验收五条逐条勾选状态 + 金额 + 签收人 + 日期 + "不含硬件上线"红字。`GET /api/business` 增加 `customers_count/quoted/contracted`，让"0 成交"这个事实从接口就能看见，而不是靠嘴解释。

**② `compute_economics` 会输出一个骗人的毛利率。**
改：`compute_economics` 增加入参 `quote_basis`、`customer_alt_cost`（客户现状成本）、`unpaid_hours`；`quote_basis != 'signed'` 时 `margin_percent` 一律返回 `null` 并附 `margin_blocked_reason`；新增 `cash_breakeven = model+voice+other`，`full_breakeven = direct_cost`，两个都返回；`efficiency` 加 `n`、`operator`、`material_id`、`scope` 四字段，且要求 `scope` 两端相等（基线缺"修改与复测"就拒绝计算 saved，直接报 `scope_mismatch`）。同时把 `hours` 改为从 `events` 时间戳汇总并附 `log_ref`，`api_calls` 增列 `prompt_tokens/completion_tokens`，`model_cost` 由成功+失败调用自动汇总。

**③ 客户付钱拿不到核心物件，验收依据文件是空的——复购与壁垒因此无从谈起。**
改：`export` 的 `05` 改为读 `test_records` 生成 T1–T9 表格（输入/期望/实际/状态/时间/版本，含 `not_run`）；`06` 改为读 `versions.diff` 输出真实差异与 `unresolved` 列表；`04` 在无音频时把包状态标 `incomplete`，并让 `export` 返回 `409` 或要求显式 `accept_degraded=true`（人工录音降级须客户书面确认）；`deliverables\04_音频\README.md` 固定串删除。再把"客户需自行完成：录音/下发/设备联调"写成 07 里的固定段落——这句反而是最硬的信任资产。

**顺带一条（30 分钟可做）**：`app.py:731` 的模板串改成从 `note` 提取一句可执行检查，并给出 `requires_human_approval=true` 的审批接口；做不到就把"改进"叙事从路演里删掉（文档 `:164` 已允许这么说）。

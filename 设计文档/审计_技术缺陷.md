# 技术缺陷审计

> 审计对象：`app.py`(848行) / `index.html` / `gates.py` / `scripts/acceptance.py`
> 方法：起服务实跑 + 构造恶意草稿直调 `validate_draft`。以下每条均已复现。
> **注意：审计期间源码被并发改写（app.py 17:09→17:20 三次，17:20 一度语法错误无法导入）。行号以 17:22 版为准。**

## P0 — 阻断级

### 1. 质量门可被整体绕过：伪造事实拿满 13/13
`app.py:396` 实体门仅 `[A-Z][A-Za-z0-9-]*`（ASCII 大写开头）；`app.py:389` 数字门仅 `\d+`。
中文专名与中文数字对两条门**完全不可见**。
- 复现：资料写"一九五八年的机床，由市机械厂捐赠"，草稿写成"**一九五零年**的机床，由**郑州机床厂**捐赠"，`facts` 只映射一句真实句。
  → `validate_draft` 返回 `passed=True, checks=13/13`。已在 17:22 版实测通过。
- 修复：实体门补 CJK 专名（机构/人名/地名）识别，或改为"讲解中每个 `<CJK专名>-后缀词`(厂/馆/院/所/公司/省/市/县) 必须 in `allowed_text`"；数字门统一走 `all_years()`（含 `cn_years`），并对中文数词 `[〇零一二三四五六七八九十百千]+` 做同样校验。
```python
# validate_draft 内，替换 389-395 与 396-400
CN_NUM = re.compile(r"[〇零一二三四五六七八九十百千]+")
CN_NAME = re.compile(r"[一-龥]{2,10}(?:厂|馆|院|所|公司|遗址|省市县)")
unsupported_cn_num = [t for t in CN_NUM.findall(narration) if t not in allowed_text]
unsupported_cn_name = [t for t in CN_NAME.findall(narration) if t not in allowed_text]
if unsupported_cn_num: issues.append("P0数字门：未支持中文数词 %s" % "、".join(unsupported_cn_num))
if unsupported_cn_name: issues.append("P0实体门：未支持中文专名 %s" % "、".join(unsupported_cn_name))
```
**根因缺陷**：`app.py:381-388` 事实门只校验"每条 fact 能否回溯"，不校验"叙述里每句是否都有 fact 覆盖"。补一句伪造成本为零。应加反向覆盖：把 narration 按句切开，每句必须命中某条 `fact["claim"]` 或 `citation["source_quote"]`。

### 2. 冲突门对项目自带资料全部失效
`app.py:194` `CONFLICT_MARKERS` 含"相互矛盾"但**不含"相互冲突"**；而 `materials/C_模拟资料_织物.md` 原文写的是"两条记录**相互冲突**"。
- 复现：`detect_source_issues(C资料)` → `conflicts=[]`。C 是**故意冲突**的样例，检测器 0 命中。
  隐式分支也失效：C 的冲突是"麻纤维/棉纤维"，非数字，`YEAR_OR_NUM` 抓不到。
- 后果：T5 场景（来源冲突并列）在服务端**根本不会触发预阻断**，`/api/generate` 直接放行生成。
- 修复：`CONFLICT_MARKERS` 补 `"相互冲突","冲突","两种说法","来源一","来源二"`；并新增非数字冲突检测——同一展项内两个句子共享高 LCS(≥6) 且各自引用不同 `来源` 段落时判冲突。

### 3. 并发 revise 触发 500 并丢更新
`app.py:803-805`：`version = row["version"] + 1` 在事务外读、再写，无锁。
- 复现：同一 run 起 8 线程并发 `/api/revise` → **6 个 HTTP 500**，错误体为
  `内部处理失败：UNIQUE constraint failed: versions.run_id, versions.version`（同时泄露表结构）。
  且失败请求的 `UPDATE runs` 可能已提交 → `runs.version` 与实际 `versions` 行数不一致。
- 修复：
```python
# 用 SQL 原子自增，冲突则重试
cur = connection.execute(
  "UPDATE runs SET draft=?,status='draft',validation=?,version=version+1,error='' WHERE id=? RETURNING version",
  (json_text(draft), json_text(validation), run_id))
version = cur.fetchone()[0]
connection.execute("INSERT INTO versions(...) VALUES(...,?)", (run_id, version, ...))
```
并用 `connection.execute("BEGIN IMMEDIATE")` 包住整个 revise，避免 `database is locked` 与丢更新。

### 4. demo 模式下"审核→导出"闭环必然断开
`app.py:409` 把"演示模板"写进 narration → 触发 `演示内容不可标记为可交付`；`app.py:815` 又对 `mode=="demo"` 直接拒批。
- 复现（`DEMO_MODE` 默认 true，即交付默认态）：`POST /api/generate` → `200 status=blocked`；`POST /api/review {approved}` → `422 DEMO模板不是AI交付证据`；`GET /export` → `409`。
- 后果：评委面前**无法演示黄金路径**，工作台永远停在"未通过"。
- 修复：demo 走独立展示通道——`status='demo_preview'`，允许导出但文件名加 `DEMO_` 前缀、`package.demo_is_delivery_evidence=false`，把"不能当 live 证据"落在产物标记上而非堵死状态机。

## P1 — 严重

### 5. 失败分支硬编码 `mode:"live"`
`app.py:777` 返回 `{"mode": "live", ...}` 无视 `DEMO_MODE`。demo 模式下的失败响应会自称 live，前端 `modeLabel()` 据此显示 **LIVE · API**。改为 `"demo" if DEMO_MODE else "live"`。

### 6. 验收脚本 T4/T5 恒为 FAIL
`acceptance.py:163,171` 判据为 `code==200 and draft.missing_materials`；服务端实际是 **409 + 顶层 `missing_materials` + 无 draft 键**。两测试必挂。改为接受 `code in (200,409)` 并从顶层取 `missing_materials`/`conflicts`。

### 7. 缺料门误检
`app.py:224,229` 以"≥12 字的句子 ≥2 句"为门槛。规范展签体（"青铜礼器甲，商代。出土于本地遗址。现藏市博物馆。"）4 句全 <12 字 → 判"资料仅 33 字、0 句可用事实，需客户补充"。**资料完整却被判缺料**，阻断生成。改为按累计字数（≥80 字）而非单句长度计。

### 8. `revise` 不校验状态，blocked 可洗成 draft
`app.py:793` 只拦 `failed`。blocked 任务 `POST /api/revise` 返回 200 且 `status→draft`，状态机失真（虽 approve 时会重新校验，不越权，但审计轨迹被污染）。补 `if row["status"]=="blocked" and not data.get("force"): return 409`。

## P2 — 一般

### 9. 负 Content-Length 导致连接挂起
`app.py:626-629` 仅拦 `> 1MB`。`Content-Length: -1` → `rfile.read(-1)` 读至 EOF，连接**永久挂起**（实测超时）。补 `if length < 0: raise ValueError`。

### 10. 无任何入站鉴权
全站无 token/session（`grep` 0 命中）。`/api/review`、`/api/revise`、`/api/runs/*/export` 任人可调，`/api/runs` 可枚举全部任务全文。黑客松可接受，但须在 README 显式标注"仅 127.0.0.1 本机演示，禁止公网监听"。建议加 `HOST` 断言。

### 11. 错误信息泄露表结构
`app.py:841` 把 `str(error)[:500]` 直接回包，暴露 `UNIQUE constraint failed: versions.run_id, versions.version`。改为按异常类型映射固定文案。

### 12. SQL 注入：无
全部 `execute()` 使用 `?` 占位符（已核 36 处）。`package_name` 对 title 做了 `re.sub(r"[^\w一-鿿-]+","_")`，路径穿越实测 `../../etc/passwd` → `_etc_passwd_...`，**防护有效**。SSRF 仅 `AI_BASE_URL` 环境变量可改，属管理员面，非远程攻击面。

### 13. `gates.py` 为死代码
`app.py` 与 `acceptance.py` 均未 import（grep 0）。其 `Rules` 可调规则集、`run_golden()` 回归集、支持度门 `longest_common_substring` 全部不生效。**当前线上只有 `app.py` 那套较弱的内联校验**。要么接入 `run_gates()`，要么删除以免评委误以为存在两套门。

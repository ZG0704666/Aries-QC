# 智能体 UI 视觉规格调研

> 说明:下文中「通行做法」为社区库、独立设计拆解与 WCAG 公开标准的汇总,非任何厂商的私有规范。ChatGPT/Claude 的数值来自第三方 CSS 逆向测量(约 720–768px 正文宽),仅作参照,不作为官方标准引用。

## 1. 排版与消息布局

核心结论:**提问用气泡,回答用无气泡正文**。原因是 LLM 输出长度不对称、含代码/表格、逐 token 流式重排;气泡会强制换行、每次重排,并压缩代码宽度。用户消息用气泡是为了表达「已提交」,不需要被细读。

| 项 | 数值 |
|---|---|
| 正文栏 max-width | 720px(纯阅读)/ 860px(B2B 含表格代码);西文场景改用 `65ch` 更稳 |
| 中文行长 | 每行 32–40 字(西文 60–75 字符,理想 66 CPL) |
| 行长依据 | WCAG 1.4.8(AAA):拉丁文 ≤80 字符、CJK ≤40;业界共识最佳 45–75,理想 66 CPL。`max-width: 720px` 在 15px 字号下约 90–96 个半角字符,故西文场景宜用 `ch` 单位 |
| 正文 | 15px / 行高 1.65(约 25px);B2B 可 14px / 1.6 |
| 用户气泡正文 | 14–15px / 1.5 |
| 辅助信息(时间、token、耗时) | 12px / 16px,颜色用 muted |
| 段落间距 | 12px(B2B 偏离 WCAG 1.4.8 AAA 的「段距 ≥1.5× 行距」是有意的:该条针对长文阅读,对话轮次本身已提供分隔。不要用固定高度容器,否则 200% 字号缩放会裁切) |
| 标题 | H1 20px/600、H2 17px/600、H3 15px/600;上间距 24px、下 8px |
| 用户气泡 max-width | 屏宽 80%,内边距 12px 上下 / 16px 左右,圆角 18–20px |
| 轮次间距 | 用户→回答 32px;回答→下一问 48px |
| 气泡内工具行距 | 6px(紧凑,B2B 常用) |

高密度 B2B 与消费级的差异:消费级可用 20px 圆角气泡 + 大留白;B2B 建议用户消息改为**左对齐 + 左侧 2px 竖线 + 浅色底**,让长文粘贴不撑爆布局,并保留时间戳/复制/重发。

## 2. 流式输出

- 光标:主流开源方案(assistant-ui / Streamdown)提供方块 `▋`、圆点 `●`、竖线三种,用伪元素挂在流式容器尾部,颜色取当前文字色或强调色,`1s step-end` 明灭。**不要用打字机定时器**:以「新到 token 才推进」的增量方式实现,否则动画始终在追赶真实流,反而增加延迟感。
- 渐进渲染:按块 memo 化 Markdown,只重渲染尾部块;容器设 `min-height: 1.5em; contain: layout` 防 CLS。
- 自动滚动必须「用户上滚即停止跟随」,回到底部 8px 内才恢复。
- 无障碍:`role="status" aria-live="polite" aria-busy="true"`,完成时置 false;**不要 aria-atomic=true**。
- 争议点:打字机效果对长回答是纯粹的等待成本,B2B 工具建议关闭,仅保留光标 + 完成态。

## 3. 智能体步骤组件

- 默认**折叠成一行**:`状态图标 · 动词短语 · 目标 · 耗时`,如「✓ 读取 3 个文件 · 1.2s」。展开看参数与结果。
- 状态图标 3 种,尺寸 12–14px:进行中 `LoaderCircle` 旋转;成功 `Check`(#16a34a / 深色 #4ade80);失败 `X`(#dc2626 / 深色 #f87171);另有 denied 用 `Ban`。
- 运行中该行整体加低对比 shimmer;结束后停止。
- 分组:相邻推理+工具调用归入一个「过程容器」,运行中默认展开,正文开始流式时自动收起。
- 例外必须强制展开:**待审批**、**失败**、正在执行且正在输出。待审批卡片应渲染在可折叠组**之外**,折叠不能隐藏用户必须执行的动作。
- 「停止」按钮全程可见;超过 10s 无进展必须显示当前步骤文字(呼应 NN/g 10s 注意力阈值)。
- 步骤行高 32px(桌面)/ 40px(触屏,整个行是可点区域;触摸目标下限 44px 不满足时用 40px + 外层 4px 内边距补齐)。

## 4. 结构化产出容器

- 文档/文件卡片:圆角 10px,1px 描边 `rgba(0,0,0,.08)` / 深色 `rgba(255,255,255,.10)`,内边距 12–14px,不投影。
- 代码块:圆角 8px,内边距 12px 16px,字号 12.5–13px,行高 1.5,**横向独立滚动**不撑破正文;右上角复制按钮 24px 命中区,hover 才显示,触摸端常驻。
- 表格:同样独立 `overflow-x: auto`,表头 12px/600,单元格 13px,行高 36px,斑马纹用 3% 透明度差。
- 所有富容器与正文同宽对齐,不加左右缩进,保持「阅读轨」一致。

## 5. 审批/确认

- 按钮层级:**主操作实心**,取消为描边/文字按钮,两者不相邻同级并列超过 2 个。
- 破坏性操作:实心红仅用于「删除/永久」;一般「发送/执行」用品牌色。危险按钮默认**不设自动聚焦**,避免回车误触。
- 二次确认形态:轻量内联确认行优于模态弹窗(不打断阅读),文案写清「将对 X 执行 Y」,并把可控参数原样展示。
- 待审批状态必须有独立的视觉暂停信号(黄色 4px 左边条 + 图标),且运行中的「停止」按钮全程可见。

## 6. 深浅色与字体

- 色彩策略:中性灰梯度 10–11 阶 + **单一强调色**。强调色只用于:主按钮、链接、焦点环、当前选中;不用作大面积背景或 AI 正文色。
- 深色不用纯黑:画布 #0b0c0a–#121212,表面层 +4%~6% 亮度;描边 `rgba(255,255,255,.10)`。浅色画布不用纯白,用 #fbfbf9–#ffffff 配 #f6f6f4 表面。
- 对比度:正文 ≥7:1(目标 7–12:1,纯黑白 21:1 反而产生光晕);辅助文字 ≥4.5:1;描边/图标 ≥3:1,对应 WCAG AA 正文 4.5:1 / 大字 3:1 / 非文本 3:1 的下限。深色模式字重下调 30–40(可变字重轴)补偿视觉膨胀。
- 强调色 B2B 首选蓝/靛(#2563eb、#4f46e5)或近黑墨色按钮;消费级可用暖橙/绿等更高饱和。
- 字体组合:UI 用系统无衬线栈(`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei"`)或 Inter/Geist;代码用 `ui-monospace, "JetBrains Mono", "Cascadia Code", monospace`,12.5–13px。**不混用两种无衬线**;中文场景务必给等宽字体补 CJK 回退,否则代码块中的中文会跳字体。

## 7. B2B 与消费级取舍速查

| 项 | 高密度 B2B | 消费级聊天 |
|---|---|---|
| 正文 | 14px / 1.6,栏宽 860px | 15–16px / 1.7,栏宽 680–720px |
| 用户消息 | 左对齐 + 竖线 | 右对齐气泡 80% |
| 过程日志 | 默认收起但常驻可见 | 全部收起,仅「思考中」 |
| 打字机 | 关闭 | 可开启 |
| 圆角 | 8–10px | 16–20px |
| 动效 | 仅状态变化,尊重 reduced-motion | 可有入场/微交互 |
| 审批 | 内联确认 + 参数展示 | 模态二次确认 |

# 调研：智能体/助手产品的前端交互范式

> 为"AI 数字员工"（B2B 展陈集成商，把展项资料变成带出处的讲解稿，多步骤、需人审、有质量门）重做界面提供依据。

## 一、为什么主轴是对话流

1. **表单要求用户先知道答案，对话允许边做边想。** Canvas 的原话是聊天"在需要编辑和反复修订的工作中受限"——但它没改成表单，而是保留聊天、加一块文档面板。共识是**补面板**，不是换掉对话。
2. **对话能承载中途改主意。** ChatGPT Agent 支持任务中打断、补指令、改方向，从断点继续不丢进度。表单只有"填完/没填完"。
3. **零学习入口。** Cursor composer、Claude 输入框、Manus 任务框都只要一句话描述目标。
4. **对话即审计日志。** Claude Code 的会话记录就是"我要求什么/它做了什么/我批了什么"的证据链——我们要回溯出处，这是刚需。

**失效边界**：产出物超一屏、需反复局部修改时，对话流就不够。Canvas 与 Artifacts 正是在"内容超 15 行且自包含"时把产物**抽出**到独立窗口。对话是主轴，产出物必须离开主轴。

## 二、产出物放哪

| 放法 | 代表 | 取舍 |
|---|---|---|
| 内联气泡 | ChatGPT 普通回答、Perplexity 答案+编号脚注 | 零成本、连贯；超一屏即滑屏疲劳，不能就地编辑 |
| 侧栏并排 | Canvas、Artifacts、Cursor 的 Review 面板 | 对话与产物**同时可见**；挤占横向空间，窄屏不可用 |
| 独立页/链接 | Artifacts 每件产物有独立分享页 | 便于评审归档；脱离对话后失去"为什么这么改"的上下文 |

值得抄的细节：
- **自动触发，不靠用户手动开**（Canvas 检测长文档自动展开）。
- **指向式修改**：Canvas 选中一段即浮出"Ask ChatGPT"，段落有独立评论气泡；Artifacts 评论可 @Claude 回传。
- **必须有版本与差异**：Canvas 顶部有前后版本箭头 + Show changes；Cursor 每轮给出 diff 可逐块接受。**没有 diff 的 AI 产物不可审核。**
- **可导出成甲方能用的格式**：PDF / Word / Markdown。

## 三、"正在工作"怎么表达

1. **步骤列表（最有效）**——Manus 左侧逐条打勾；Devin 先给一份**可编辑计划卡**，改完再执行。用户焦虑的不是"它卡了吗"，而是"它理解对了吗"，步骤列表是最便宜的纠错窗口。
2. **流式输出**——只证明"在打字"，不证明"在推进"。Perplexity 边写边挂编号引用，能立刻看出来源对不对。
3. **一行当前动作 + 耗时**——Claude Code 底部 `正在运行 xx · 12s`，干扰最小，适合长工具调用。
4. **思考折叠**——可审计但不打扰；非技术用户展开也看不懂，属留痕而非体验。
5. **进度条（最不可靠）**——步数往往事后才知道，只能是假的，卡住反放大焦虑。

比动画更重要：可暂停、可要进度摘要、可拿半成品（ChatGPT Agent 三者皆有）。

## 四、需要人确认的动作

1. **分级，不阻断。** Claude Code：读文件/搜索不打断；写文件、跑 shell、发请求才确认。确认框给四选项——本次允许 / 本会话允许这类 / 拒绝 / **拒绝并说明理由**（最有价值，让用户纠正而非重来）。
2. **确认框里放"将要发生什么"。** Claude Code 编辑确认直接展示 diff，终端确认展示完整命令；Cursor 跑命令前展示命令，可改。空泛的"确定吗"最易误点。
3. **审批是状态，不是弹窗。** Cursor Plan 模式、Claude Code plan mode：先出可审阅计划，批准后执行。ChatGPT Agent 对有真实后果的动作（发邮件、下单）强制显式确认。

防误点：破坏性操作二次确认、默认焦点落在"取消"、拒绝必填理由。模态弹层只留给不可逆操作；日常审批用列表卡片，可边看产物边批。

## 五、输入区（composer）

- 多行 + Shift+Enter 换行，已是事实标准。
- 附件：Projects 的 project knowledge 允许整批文档常驻，免去重复上传。
- `@` 引用：Cursor 可引文件、符号、历史对话。本质是**把"指的是哪个东西"从自然语言里解放出来**。
- `/` 命令：`/canvas`、`/permissions`，适合高频无歧义的固定动作。
- **模式切换最有价值**：Cursor Shift+Tab 轮转 Ask/Agent/Plan；Claude Code 轮转 default/acceptEdits/plan，**当前模式常驻状态栏**（`⏸ plan mode on`）。一次按键交出"要不要动手"的控制权，胜过任何设置页。

## 六、空状态

给模板不给说明（Artifacts 有模板与画廊）；给**真实产物样例**；把能力边界写在空状态——ChatGPT Tasks 的教训是用户不知它非确定性，于是用错场景。

## 七、不适用于我们场景的范式

1. **逐块 diff 接受/拒绝——不适用。** 那是为代码设计的离散 hunk。讲解稿是连贯叙述，逐句点选会疲劳，且**出处与文字绑定**，接受一句却丢来源就是质量事故。我们要"版本对比 + 门禁整体放行"。
2. **Canvas 自动弹/收侧栏——不适用。** 被用户抱怨"自作主张"。产出物是唯一交付物，应常驻。
3. **"对话即全部入口"——不适用。** 工程师知道该说什么；我们的用户是项目经理和文案，面对空框只会写"帮我写讲解稿"。必须**模板起手**。
4. **Manus/Devin 式全自主跑到底——不适用。** 没有可执行环境，风险不在误删文件，而在**内容真实性**（编造的年代、错误的策展人）。全自主等于把审核压到最后一刻。
5. **公开分享链接/画廊——不适用。** 展项清单常带 NDA，应走项目内三级权限（private/view/edit）。
6. **后台长任务+完成通知——半不适用。** 交付有截止日，用户要"现在停下等我确认"，不是"跑完再推给你"。

## 八、我们该怎么设计

**1）主轴：以"展项"为单位的审核工作台，对话降为协作通道。**
三栏：**左＝步骤/质量门轨道（固定窄栏）｜中＝讲解稿主编辑器（常驻、最大）｜右＝对话+出处抽屉（可收起）**。
对话流适合从无到有，我们的任务大半是从有到对。窄屏退化为"稿子+底部抽屉"。

**2）产出物：中间常驻 + 段落级出处徽标。**
**每个事实句右侧挂出处徽标**，点开显示来自哪份资料、第几页、原文片段——把 Artifacts 的段落评论气泡挪用到溯源上，比 Perplexity 的文末脚注更适合长文档。顶部固定"版本对比（红绿高亮）"与"导出 Word/PDF"。

**3）步骤：一条轨道 + 一行状态。**
左轨固定五阶段：**导入资料 → 提取事实 → 生成初稿 → 出处核对 → 人工审核**，完成的打勾可展开看产出了什么。第一步是可编辑计划卡（可删掉不需要的展项，抄 Devin）。执行中只显示 `正在核对第 7 段出处 · 12s` + 暂停/详情。**不画百分比**，用"五个门过了两个"表达，比 37% 诚实且可解释。

**4）审批：门禁卡，不用模态框。**
到门禁时在稿区顶部插入卡片："42 句有出处，3 句缺出处，2 句冲突"，按钮为 `查看缺出处的句子 / 退回重做 / 通过`。只有发布、删除、覆盖甲方版本走模态二次确认且默认焦点在取消；拒绝必填理由并回灌智能体；审批落成"谁在何时批了什么"。

**5）输入区：模板起手 + @ + / + 模式切换。**
空框上方三张起手卡（"3 分钟导览版""8 分钟详版""按动线重排"）＋"或直接描述"。`@` 引展项/资料/上一版稿件，`/` 提供"重写本段、补出处、换语气"。右下常驻模式：**`严格`（每句必带出处）/ `快速`（先出稿后补）**。

**6）空状态：放一份已完成的样例稿。**
首屏是一份标注满出处徽标的成品，可滚动、可点徽标，旁白："你的资料，变成这样。"并写明边界："我们不做展项判断，终稿需要你的审核。"

**一句话**：抄 Canvas/Artifacts 的"产物常驻+版本对比+指向式修改"，抄 Manus/Devin 的"步骤轨道+可编辑计划"，抄 Claude Code 的"分级权限+带理由的拒绝"；丢掉逐块 diff、自由对话入口、公开分享。

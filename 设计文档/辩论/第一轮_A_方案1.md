# 第一轮 · 辩手 A：为方案1辩护

> 方案1 = 《PRD 与执行方案1》（V2.0 智能体搭建版）；方案2 = 《PRD 与执行方案2》（作战手册）；方案3 = 《展览语音体验交付_48小时参赛方案》。

## 一、立论：方案1 为什么最能拿分

**AI 员工完成度（30）：唯一能当天开工的施工图。** 第二部分把岗位直接落成 1 份人设、3 个技能（来源映射、讲解生成、影响检查）、1 条六步 SOP，并挂上两道 P0 门：“资料缺失时，禁止进入第 3 步”和“音频/文案数量必须等于展项数量”。规模正好符合方案2 自己定的出口标准“≤1 SOP + 2-3 个技能”。附录的启动 Prompt 可以直接交给编码 Agent。方案3 只写了岗位“做什么”（§3、§3.1），没写“怎么造”，48 小时里要先花时间把它翻译成实现。

**商业闭环（30）：一个买单方，一个范围，一个价格。** 第一部分第 2 节定了集成商买单、策展人审核；第 3 节把交付边界压到“单展厅 / 3 展项 / 1 语言 / 1 轮修改”；第六部分第 5 段给出“3000 元/试点”。评委 30 秒内就能听懂买卖关系。

**创新性（25）：防串台与可量化效率。** 第三部分红线 2“展项 A 的特征绝不能出现在展项 B 的讲解里”抓住了多展项场景特有的事故。第一部分第 4 节给出效率锚“1-2 天 → 2-3 小时”，路演能讲出数字。

**演示表达（15）：叙事好记，边界写成红线。** 第六部分“眼睛能看 / 脑子能转”把旧硬件和新员工分开讲。第三部分红线 3“绝不声称已上线眼镜”把硬件约束写进 AI 的行为规则，不只在 PPT 上做说明。

## 二、批判方案2：一本通用模板，没有一个字讲本赛题

1. **展览业务完全空白，商业闭环得零分。** 全文没有展陈集成商、展项、价格或客户；唯一的“范例锚点”是“20 个 XRD 样品……峰位/FWHM”（Phase 0）。商业部分只有“政策锚点”（§1）引用国务院文件，政策不等于有人付钱。
2. **无视眼镜和离线约束。** 全文没有提到眼镜、端侧识别或不能联网，团队唯一的实物资产在路演中没有位置。
3. **依赖一个没说明的运行时。** §2 称“运行时引擎（你不碰）……当作黑盒调用”，但没说是哪个运行时、团队是否已有。仓库里现有的是自写的 `exhibit_ai_employee/app.py`，与“不需要写一行底层引擎代码”（开头说明）对不上。
4. **处处卡在“人来定”，三人团队会停摆。** Phase 0 的 5 个框定问题全部标【人来定】，并要求“答不出 → 先别造”。可团队里没有展陈领域专家，按它的规则 Phase 0（≤6h）就可能出不去。
5. **要数字，却不给测量方法。** Phase 3 要求“N 小时→M 小时、通过率 Y%”，但没有展览场景的基线输入集。到了台上只能编数字，正好违反它自己的“第一铁律”。

## 三、批判方案3：写得最细，也最容易在 48 小时里垮掉

1. **它卖的东西客户用不上。** §1.1 承认新增脚本不能导入眼镜，§2.2 的试点包却仍包含“无目标/多目标/切换提示”和场景测试。集成商花 3000 元买到的过渡话术，在它自己的设备上播不出来。§8 第 4 条自己承认“应承认交付缺口”。评委只要问一句“你测的是客户设备还是你们自己的模拟器”，就答不上。
2. **范围失控，违反它自己的规则。** P0 包含 T1-T10、连续 3 次复测、外部审核人、7 状态模拟器（§4.1 带 1/2/5/30 秒阈值）和 7 文件交付包。§6 说“不要三个人同时做三个独立产品”，却让 C 全程做模拟器，这本身就是一个独立产品。
3. **排期不现实。** §6 把“与潜在客户访谈”排在 11/15 00:00–10:00，凌晨联系不上集成商。§2.3 又把商业验证建立在这些访谈上。
4. **自我否定，拖累路演。** §2.2 写“不是市场价或收入预测”；示例里人工要 12 小时，贡献 1500 元；§5.2 又写“不计算节省百分比”。评委会问“AI 员工到底省了什么”，方案3 没有一个数字可以拿出来。
5. **怎么造只字未提。** §8 第 3 条到最后还在问“是否具备可稳定使用的模型与语音服务”。占 30% 的完成度建立在一个尚未回答的问题上。

## 四、方案1 的真实弱点与补法

1. **商业闭环太薄。** 方案1 只有一个价格，没有成本公式、获客、收款节点和复购。**补：** 吸收方案3 §2.2 的贡献公式和验收边界、§2.3 的五步闭环，价格旁边标注“待访谈验证”。
2. **效率锚未经测量，也有前后矛盾。** “1-2 天 → 2-3 小时”没有基线。第一部分第 4 节写 T1-T10，第四部分只列了 T1-T8，漏掉抖动和来源冲突。第三部分写多目标“按默认静默处理”，T3 写“提示选择”，两处不一致。**补：** 恢复 T1-T10；用方案3 §5.2 的测量模板实际计时，路演只报实测数字。
3. **模拟器规则缺失，与现有原型有差距。** SOP 第 4 步要求“场景自测”，但方案1 没有定义状态规则。现有 `app.py` 产出的是 80-160 字的问答互动卡，不是 30-60 秒讲解，也没有 diff 功能。**补：** 从方案3 §4.1 只取无目标、多目标、切换三个状态；从方案2 吸收“红线探针”（断网、施压时不编造）和“改动留 CHANGELOG”，作为完成度的证据。

**结论：** 以方案1 的五机制骨架为主干，嫁接方案3 的商业公式和测量模板，砍掉方案3 的大部分模拟器范围。方案2 只取它的检查清单。
